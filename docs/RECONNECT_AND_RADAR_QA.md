# FIRETEAM - Match Reconnect and Cabin Fever radar (alpha QA)

Status: source committed to main. Windows compilation and multiplayer runtime tests are PENDING.

## Alt+F4 rejoin exploit

Before this change, the server created a new CPlayerSrvr with 100 HP and 3 lives on every join. It destroyed the state on disconnect.

The server now keeps a match-scoped state snapshot keyed by a 128-bit random ticket generated by Windows BCryptGenRandom. Clients keep their own ticket across sessions under:

    %LOCALAPPDATA%\FIRETEAM\reconnect-<player-name>.token

The client never supplies HP/lives/score or ammo. It only sends the ticket with the existing player-name packet. The server restores its own snapshot with health, lives, stats, position, original safe respawn anchor, remaining ammunition (for matching weapon IDs), and the active death timer. A duplicate ticket that is already online cannot claim the state. A server world restart clears the store.

Fresh identities arriving after a round has begun wait until the next round, preventing the trivial workaround of deleting the ticket and immediately obtaining another full-health player mid-wave. They receive a JOINING AT NEXT ROUND HUD message.

Limitations: This is not a central account service. Players can still create second identities and join a later wave. True strong identity protection needs server policy or account authentication. The restart registry is server memory only. All clients must build the same new protocol version. Loadout changes remain allowed, but changing weapons does not transfer ammo from another weapon.

## Cabin Fever radar

The client draws a code-generated, circular radar top-right. It does not depend on third-party DTX files.

The server sends no more than 64 short-lived, heading-relative teammate/zombie offsets, quantized into signed 8-bit coordinates, 2 times per second. Radius is 1150 horizontal units with up to 170 units of elevation difference.

Colors: WHITE center=self; GREEN=teammate; RED=ordinary infected; ORANGE=Tanker; PINK=Assassin. Players facing forward will always face up on radar. Missing stale snapshots expire in 2.5 seconds.

Launcher Settings > Display > TOP-RIGHT RADAR toggles visibility. Defaults on and appends an optional eighth token to fireteam-settings.cfg (seven-token legacy settings still parse). Command-line testing also accepts +ftradarenabled 0.

## Look for authentic CA radar assets

The Cabin Fever screenshot confirms the original game had this HUD, but not which underlying DTX or code draws it. Use original visuals ONLY when a validated file can be found and staged.

Place owned FX.zip, Textures.zip or HUD ZIPs into assets-local, then run:

    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\audit-radar-assets.ps1

Alternatively set -ArchiveRoot to a folder containing the ZIPs.
See assets-local\Reports\radar-asset-audit.txt for names. It never extracts or uploads assets. Connected Google Drive search currently did not surface named archives.

## Windows validation

1. Close the game, launcher and dedicated server.
2. Run git pull --ff-only then build.cmd and build-dedicated.cmd (if hosting headless).
3. Verify ordinary single-player joins and settings radar ON/OFF work.
4. Connect to multiplayer, take damage, record health/lives/kills/ammo and position. ALT+F4, reopen with the same nickname. All values must match or legitimately decrease.
5. Repeat mid-respawn and OUT OF LIVES; no new free health/lives.
6. Join with a NEW nickname while a wave is active; expect a wait state until the following round, then a normal first spawn.
7. Test two different Windows PCs, distinct player identities, and both being reconnected independently.
8. Confirm teammate and zombie radar dots move as you turn/walk, and that the Tanker and Assassin colors appear.
9. Verify existing round logic, crosshair, hit blood burst, health HUD and stats remain intact.

These commits have not been compiled with MSVC or playtested by the authoring assistant.
